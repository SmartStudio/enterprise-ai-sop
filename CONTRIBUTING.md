# Contributing

This repository is a **public blueprint**, not an application. We take edits that make the SOP clearer, more testable, or safer to adopt. We do not take product feature requests, trading bots, or “please add my tool” ads.

## Category line (do not rewrite)

企业 AI 落地 SOP——先写清边界，再自动化。  
Public SOP for enterprise AI: write the boundary before you automate.

## Before you open an issue

1. Read the README first screen and the five-stage exit tests.
2. Search existing issues.
3. If you are new, look for the `good first issue` label.

## Good first issue

A `good first issue` must be all of:

- One file, or one section of the README
- No client-identifying material
- A concrete acceptance line in the issue body (“README Diagnose exit test names Legal + business owner”)

Do not mark strategy debates or new-stage proposals as good first issues.

## Pull requests

- One change per PR.
- Keep the first screen answering: what / who / why better / where to click.
- Do not add customer names, keys, or vendor login instructions.
- If AI assisted the diff, say so in the PR body (`AI-assisted: scope X`).

## Review

Maintainers review for: boundary-first wording, exit-test clarity, and whether the change still reads as a methodology (not a product).
